# Question generation playbook (draft → review → publish)

Reusable path for any exam already stored in `examtracker`.

## One-time setup

1. Run SQL migration: [`supabase/migrations/add_examtracker_status.sql`](../supabase/migrations/add_examtracker_status.sql)
   - Adds `status` (`draft` | `published` | `rejected`), `published_at`, `published_by`
   - Backfills existing rows as **published**
   - Updates syllabus/count RPCs to count **published only**
2. Confirm admin email is in `ADMIN_EMAILS` / `NEXT_PUBLIC_ADMIN_EMAILS`
3. **PostgREST note:** until the API schema cache exposes `status`, the app also mirrors lifecycle into `verification_status`:
   - draft → `unpublished_draft`
   - rejected → `publish_rejected`
   - published → cleared / non-sentinel
   Practice filters use this mirror. Publish APIs write **both** columns via Postgres.

## Flow

```
Generate (status=draft) → /admin/question-review → Publish (single | selected | all matching)
                                                      ↓
                                         Live in practice + mocks
```

- Drafts never appear in practice, hubs, or mock bank pickers.
- Bulk JSON import defaults to **draft** unless the row sets `"status":"published"`.

## GATE CSE · Computer Networks (first pack)

**Config:** [`src/lib/question-gen/config.js`](../src/lib/question-gen/config.js) → `GATE_CSE_CN_CONFIG`

- Subject: `computer-networks`
- Chapters: `osi-layer`, `physical-layer`, `data-link-layer`, `network-layer-protocol`, `transport-layer-protocol`, `application-layer-protocols`, `network-security`
- Default mix: **5 easy + 5 medium + 5 hard per chapter**
- NAT/math items verified by [`cnMath.js`](../src/lib/question-gen/cnMath.js)

### Generate

**Admin UI (preferred):** `/admin/question-review` → **Generate CN drafts**

**API:**

```http
POST /api/admin/examtracker/generate
Content-Type: application/json

{ "countsByDifficulty": { "easy": 5, "medium": 5, "hard": 5 } }
```

Dry run: `{ "dryRun": true }`

**CLI:**

```bash
cd cattracker
node --env-file=.env.local scripts/generate-gate-cn-drafts.mjs --dry-run
node --env-file=.env.local scripts/generate-gate-cn-drafts.mjs --easy=5 --medium=5 --hard=5
```

### Review & publish

1. Open `/admin/question-review`
2. Filter: Category `GATE-CSE`, Subject `computer-networks`, Status `Draft`
3. Click **Preview** on a row — **Student preview** tab shows how it will render on the practice page (stem, diagram, code, options/NAT, optional solution)
4. Switch to **Edit fields** if needed → Save → **Publish**
5. Or multi-select → **Publish selected** / **Publish all matching**

Image / code drafts: `scripts/insert-cn-image-drafts.mjs` (or full refresh via `scripts/regenerate-cn-drafts.mjs`) uploads SVGs to `mcq-images/gate-cn/drafts/` and inserts diagram + code questions as drafts.

Gap-fill (thin topics, insert-only, never deletes published): `scripts/generate-cn-gap-drafts.mjs` using `GATE_CSE_CN_GAP_CONFIG` (routing, MAC/ALOHA, delays, devices, subnetting, TCP/UDP, email/FTP, security extras).

Generated items:

- `year` = **`generated by 10tracker.com`** (attribution). `topic` stays the syllabus topic only.
- `solutiontext` = detailed written solution (HTML + MathJax `$...$`).
- `solution` = **empty** unless there is a real GateOverflow discussion URL — never invent a GO link.
- Never append “Variant N” / “Set N” labels.

## Copy for another exam / subject

1. Confirm `category`, `subject`, and `chapter` strings already used in your bank (or create them consistently).
2. Add a config object next to `GATE_CSE_CN_CONFIG`:

```js
export const MY_EXAM_CONFIG = {
  category: 'GATE-EE',          // examtracker.category
  subject: 'networks',          // examtracker.subject
  status: 'draft',
  countsByDifficulty: { easy: 5, medium: 5, hard: 5 },
  chapters: [
    { chapter: 'chapter-slug', topic: 'Display topic', generator: 'network' },
  ],
};
```

3. Wire generators in [`cnTemplates.js`](../src/lib/question-gen/cnTemplates.js) (or a new `*Templates.js`) and register them in `GENERATORS`.
4. Point `POST /api/admin/examtracker/generate` (or a new route) at that config.
5. Generate → review → publish. No second publish system.

## Accuracy rules

- Generation is **built-in templates + math checks** (Cursor/agent managed). **No OpenAI key** is required for the CN pack.
- Prefer **parametric templates + deterministic checks** for NAT (CIDR, fragments, CRC, windows).
- Conceptual MCQs still need **human review** before publish.
- Do not paste copyrighted PYQ stems; generate originals in the same difficulty band.
- Images: set `questionImage` URL on the row when a diagram is required; review in the drawer before publish.
